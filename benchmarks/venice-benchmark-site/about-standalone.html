Methodology

What the columns mean

  • Score (0–100) is a hand-tuned rubric per benchmark: intent-class accuracy and structure; UI generation code-runs-and-renders; startup-in-a-weekend feasibility; value density under a 1K token budget; reverse-prompt vision checklist hits; pharma-ddi drug-pair identification; regulatory comprehension of WHO/FDA citations. Brick Breaker is retired and not scored.
  • Cost is reported in USD using Venice's /v1/models pricing at run-time, multiplied by token counts consumed.
  • Latency is the wall-clock between request and final token. Long-tail latencies (300–510 s) reflect reasoning-heavy models that produce long completion bodies; this is on purpose — see the harness-cap change on 2026-07-24.
  • Score / $ is average score divided by total cost; higher = better value.
  • VivIndex is a five-track weighted composite: startup 25%, intent 20%, value density 20%, reverse-prompt 20%, UI 15%. Pharma is charted separately. Missing core tracks renormalize weights.
Sources

Where this lives on disk

  • data/results.json — every (model, benchmark) pair with status, score, latency, tokens, cost.
  • data/changelog.json — the source of truth for this page.
  • model_registry.py — model roster; adding a model here is one of two ways to onboard it (the other is editing add() directly).
  • run_benchmarks.py --run-real --model <id> — CLI for re-running any model.
  • run_new_tracks.py — Value Density + Reverse-Prompt Vision runner.
  • data/vision/ + vision.html — reverse-prompt fixture and gallery.
  • generate_standalone.py — rebuilds benchmarkviv-standalone.html (and now about-standalone.html) for offline use.
