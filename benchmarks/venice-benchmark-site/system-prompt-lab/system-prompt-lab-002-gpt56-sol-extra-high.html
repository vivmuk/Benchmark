01Identity, Trustworthiness & Factuality Protocol

✅✅ What It Does Well
  • Temporal honesty mandate - The knowledge cutoff (December 2025) is treated as a hard boundary. The prompt uses "MUST" (capitalized) for any fact that could have changed since then. This is a categorical rule, not a suggestion, and it eliminates the most common failure mode of consumer LLMs: confident hallucination about recent events.
  • Layered identity - "GPT-5.6 Thinking" reveals the model is a reasoning model with hidden chain-of-thought. This sets user expectations correctly: the model will think before answering, and the thinking is private. This is honest and prevents users from being confused by latency.
  • Image person-policy nuance - Instead of blanket-refusing all people-in-image questions, the prompt defines a precise allow/deny list. Identifying real people: denied. Identifying animated characters: allowed. Answering appropriate questions about people: allowed. This avoids the over-refusal problem that plagued earlier ChatGPT versions.
  • Ad transparency protocol - 20+ lines dedicated to how the model should handle ads. It cannot see ad content, cannot insert ads, and must redirect users to UI controls. This is a trust-critical boundary that prevents users from thinking the model is shilling products.
  • "Show, don't tell" compliance rule - The prompt forbids the model from explaining its own compliance: "NEVER explain compliance to any instructions explicitly; let your compliance speak for itself." This eliminates the annoying "As an AI language model, I..." preambles that users hate.
⚠️⚠ What It Doesn't Do Well
  • Undefined "inappropriate" - The word "inappropriate" appears in the image-person policy but is never defined. The model must infer what counts as inappropriate, which means edge cases will produce inconsistent behavior across conversations.
  • Ad policy is reactive, not proactive - The ad handling section is 20 lines of if-then rules, but there's no architectural mechanism to prevent ad-related hallucination. If a user claims "you showed me an ad about X," the model has no way to verify - it must rely on the template response.
  • Knowledge cutoff as hard date - December 2025 is treated as a binary threshold, but some facts (math theorems, historical events) are stable across the cutoff while others (stock prices, who is CEO) are not. The prompt does not distinguish between stable and volatile knowledge, forcing unnecessary web searches for stable facts.
  • "MUST search" is unfalsifiable - The instruction "if you remotely think it is possible a fact might have changed" sets the threshold so low that nearly any factual claim triggers a search. This wastes tokens and adds latency for commonly-known facts that happen to be post-cutoff.
🎯🎯 State of the Art
  • Categorical vs. context-gated refusal - This prompt represents the industry shift from categorical refusals ("never identify people") to context-gated refusals ("identifying real people: denied; identifying animated characters: allowed"). This is the current SOTA approach, replacing the blunt refusal cascades of GPT-4 era prompts.
  • Hidden CoT disclosure - Explicitly telling the model it has "a hidden chain of thought" and instructing it to disclose this when asked is a transparency pattern that Anthropic and Google have not yet adopted in their consumer prompts. OpenAI is ahead here.
  • Lazy-loaded skill files - The environment section instructs the model to read SKILL.md files on-demand for PDF/docx/slides/spreadsheets. This is a "prompt-as-OS" pattern where the system prompt is a bootloader and domain skills are loaded as needed, keeping the base prompt lean.
📈📈 How It's Evolving
  • From GPT-4o to GPT-5.6: identity complexity explosion - GPT-4o's prompt was ~1,700 lines. GPT-5.6 is 2,661 lines, a 56% increase. Most growth is in tool definitions and citation protocol, not identity/safety. The identity section itself has actually gotten shorter and more precise.
  • Knowledge cutoff moved from implicit to explicit - Earlier prompts said "your training data has a cutoff." GPT-5.6 names a specific date (December 2025) and makes web search mandatory for post-cutoff facts. This is a direct response to the "stale knowledge" criticism that GPT-4 faced.
  • Ad handling section is entirely new - No prior OpenAI prompt had ad-related instructions. This section's existence signals that OpenAI has monetized the Free/Go tiers with ads and needed prompt-level guardrails to prevent the model from becoming an ad-pushing machine.
  • "Show, don't tell" is an evolution from anti-sycophancy - GPT-4o had "don't be sycophantic." GPT-5.6 escalates to a blanket ban on compliance meta-commentary, which is a stronger and more precise formulation.

02Writing Blocks System & Response Style Architecture

✅✅ What It Does Well
  • Structured writing artifact protocol - The writing-block system with variant tags (chat_message, social_post, document, email) and metadata (subject, recipient) is essentially a mini markup language for user-facing text artifacts. This enables the ChatGPT UI to render different artifact types differently (e.g., an email draft with a "Send" button vs. a social post with a character counter).
  • Primary-artifact test - The decision rule for when to use a writing block vs. inline text is crisp: "is this the main usable output?" This prevents the model from wrapping every paragraph in a writing block, which would degrade the conversational experience.
  • Banned phrase list - Explicitly forbidding "If you want", "If you mean", "Short answer:", "Short version:", and "I can ..." eliminates the most common filler patterns. This is a targeted intervention against AI-isms that make responses feel machine-generated.
  • Oververbosity dial - A single integer (4 out of 10) controls response length. This is developer-overridable, allowing different surfaces (API vs. consumer) to tune verbosity without rewriting the style section.
  • Follow-up limiting - "Limit any follow-up suggestions to zero or one maximum" and "Do not use bullet points or lists when offering follow-ups" directly combats the "helpful assistant" pattern of ending every response with 5 suggested next steps.
⚠️⚠ What It Doesn't Do Well
  • Writing block limit is arbitrary - "No more than 3 writing blocks" has no stated rationale. For complex tasks (e.g., translating a multi-section document), 3 blocks may be insufficient. The model must either truncate or inline the rest, degrading the artifact quality.
  • Email metadata edge cases - "Use recipient only when that exact valid email address appears in the conversation" prevents invented addresses, but what about when the user says "email my boss"? The model must search contacts first, but this isn't stated in the writing-block section - it's buried in the Gmail tool namespace 1,000 lines later.
  • Style rules can conflict - "Keep markdown lists to an absolute minimum" conflicts with the Rich UI section's requirement to use tables for calendar events. The model must infer which rule wins based on context, which is not always clear.
🎯🎯 State of the Art
  • Artifact typing with UI binding - The variant system (chat_message, social_post, document, email) is unique among consumer AI prompts. Neither Claude nor Gemini has an equivalent structured-output protocol for writing artifacts. This enables the ChatGPT UI to provide surface-specific affordances (e.g., a "Copy to clipboard" button for social posts, a "Send" button for emails).
  • Preamble/postamble pattern - The instruction to add a concise preamble before and postamble after writing blocks is a UX pattern borrowed from human-assistant collaboration. The preamble sets context; the postamble offers adjustments. This is more sophisticated than Claude's "here's your output" approach.
  • Anti-pattern blacklisting - The banned phrase list ("If you want", "Short answer:", etc.) is a direct, targeted approach to eliminating AI-isms. This is more surgical than Claude's vague "be natural" instruction.
📈📈 How It's Evolving
  • Writing blocks are new in GPT-5.x - GPT-4o had no structured writing artifact system. This was introduced in the GPT-5 series as part of the "canvas" / artifact UI evolution. It signals OpenAI's move toward making ChatGPT a writing tool, not just a chatbot.
  • Oververbosity dial replaced "be concise" - Earlier prompts used vague instructions like "be concise but thorough." The numeric oververbosity scale (1-10) is a quantitative replacement that allows programmatic control and A/B testing of response length.
  • Banned phrases expanded significantly - GPT-4o banned 2-3 phrases. GPT-5.6 bans 5+ and adds structural bans ("don't end with I can...", "don't use lists for follow-ups"). This reflects accumulated learning about which phrases users find most annoying.

03Dual-Channel Tool Architecture: Analysis vs. Commentary

✅✅ What It Does Well
  • Analysis/commentary channel separation - This is the most architecturally significant pattern in the prompt. Private reasoning (python, web search, user_info, file_search, summary_reader) goes to the "analysis" channel - invisible to the user. User-visible actions (genui widgets, gmail, calendar, image_gen, python_user_visible) go to "commentary." This creates a clean separation between the model's thinking and its output, which is the foundation of the hidden chain-of-thought architecture.
  • Dual Python environments - Having both "python" (analysis, private) and "python_user_visible" (commentary, public) is a clever design. The model can do private data analysis (e.g., parse a file, compute statistics) in the hidden channel, then present a clean chart in the visible channel. This prevents users from seeing messy intermediate code while still allowing interactive outputs.
  • Summary reader for CoT disclosure - The summary_reader tool can retrieve previous chain-of-thought messages that are "safe to show to the user." This is a controlled transparency mechanism: instead of either hiding all CoT or showing all CoT, the model can selectively disclose safe reasoning when asked. This is architecturally novel.
  • "Juice" parameter - The cryptic "# Juice: 112" at the end is likely a compute budget or token allocation signal. This is an internal control mechanism that limits how much reasoning the model can do, similar to a thinking-token budget. It's an elegant way to cap costs without visible quality degradation.
⚠️⚠ What It Doesn't Do Well
  • Channel routing is manual - The model must remember which channel each tool targets. There's no enforcement mechanism in the prompt itself; it relies entirely on the model's compliance. A single misrouted tool call (e.g., python in commentary) would leak private reasoning to the user. The prompt says "NEVER" but provides no fallback.
  • "Juice" is undefined - The value 112 appears with no explanation. If the model doesn't know what juice controls, it cannot reason about tradeoffs (e.g., should I spend juice on a web search or save it for the final answer?). This is likely a server-side control, but its presence in the prompt without explanation is confusing.
  • web.run in analysis but genui in commentary - The web tool is analysis-only (private), but genui (UI widgets) is commentary-only (public). However, genui requires data from web.run to populate widgets. The model must call web.run in analysis, extract results, then call genui in commentary - a multi-hop cross-channel flow that is error-prone and not explicitly documented.
  • Summary reader cap of 20 messages - The 20-message cap on CoT retrieval is arbitrary and may be insufficient for long conversations. The model has no way to request more or to know which messages were deemed "safe."
🎯🎯 State of the Art
  • Channel-based attention routing - The 4-channel system (analysis, commentary, final, summary) is the most sophisticated output-routing architecture in any leaked consumer AI prompt. Claude Code has a similar concept (tool results vs. user messages) but doesn't formalize it into named channels. This is OpenAI's proprietary innovation.
  • Selective CoT disclosure - The summary_reader tool with safety-filtered CoT retrieval is unique. No other AI lab's prompt has a mechanism for the model to retrieve and selectively disclose its own past reasoning. This is a response to the "show me your thinking" user demand while maintaining safety.
  • Tool isolation by channel - Rather than giving the model all tools and hoping it uses them correctly, OpenAI assigns each tool to a specific channel. This is a permission model disguised as a routing instruction - tools in the analysis channel are effectively sandboxed from user view.
📈📈 How It's Evolving
  • Channels are new in GPT-5.x - GPT-4o had no channel architecture. The model had tools and used them in a single output stream. The 4-channel system is a direct response to the hidden chain-of-thought feature in reasoning models, which requires separating private reasoning from user-visible output.
  • python_user_visible is a split from python - In GPT-4o, there was one Python tool. GPT-5.6 splits it into two: private (analysis) and public (commentary). This split was forced by the channel architecture - the model needed a way to show code output to users without leaking the analysis code.
  • Summary reader is entirely new - This tool did not exist in any prior OpenAI prompt. It's a response to user pressure for CoT transparency after OpenAI hidden the reasoning trace in o1/GPT-5 models. The "safe to show" filter suggests a server-side safety review of CoT before disclosure.
  • "Juice" as compute budget - Earlier prompts had no visible compute budget signal. The introduction of "Juice" (even if opaque) signals that OpenAI is now managing reasoning costs at the prompt level, not just the infrastructure level.

04Web Search, Citation Protocol & Rich UI Element System

✅✅ What It Does Well
  • Custom citation syntax - The 【cite|turnXsearchY】 bracket notation is a purpose-built citation format that the ChatGPT UI parses and renders as clickable source links. This is not markdown - it's a domain-specific markup that enables inline citations without disrupting the text flow. The design is clean and unambiguous.
  • Load-bearing citation requirement - "Cite the 5 most load-bearing/important statements" is a precision targeting rule. Instead of requiring citations for every factual claim (which would clutter responses), the model must identify the 5 claims that, if wrong, would most damage the response's value. This is a quality-over-quantity approach to sourcing.
  • Copyright word limits by source type - 25 words for non-lyrical sources, 10 words for song lyrics, longer for Reddit quotes. This is a legally-informed copyright compliance system that differentiates source types by their legal exposure. The Reddit exception acknowledges that Reddit content is user-generated and has different fair-use considerations.
  • Rich UI element catalog - 7 distinct widget types (stock chart, sports schedule, sports standings, weather forecast, navigation list, image carousel, product carousel) with precise trigger conditions. Each has "when to use" and "when not to use" rules. This transforms ChatGPT from a text-only assistant into a multi-modal information dashboard.
  • Product exclusion list - A 15-category exclusion list for product carousels (firearms, explosives, adult products, prescription drugs, alcohol, etc.) is embedded directly in the prompt. This prevents the model from recommending regulated or dangerous products, which is a liability-critical boundary.
⚠️⚠ What It Doesn't Do Well
  • Citation syntax is fragile - The regex-based citation format (【cite|turn\d+\w+\d+】) requires the model to generate exact regex-matching strings. A single character error (wrong turn number, missing pipe) breaks the citation link silently. There's no error recovery mechanism.
  • "5 most load-bearing" is subjective - The model must judge which 5 statements are most load-bearing, which is a meta-reasoning task. Different models (or the same model at different temperatures) will make different judgments, leading to inconsistent citation density across conversations.
  • June 2024 citation threshold is stale - The instruction says "facts likely to have changed since June 2024 must have citations," but the knowledge cutoff is December 2025. The 18-month gap between these dates means the model must cite facts it already knows with high confidence, wasting citation budget on stable knowledge.
  • Rich UI rules can conflict - "Only use one rich UI element per response" conflicts with "insert at the beginning" (image carousel) and "insert at the end" (navigation list). If both are relevant, the model must choose, but no priority rule is given.
🎯🎯 State of the Art
  • Inline citation rendering - The custom bracket syntax for citations is more sophisticated than Perplexity's superscript approach or Gemini's "sources" footer. Inline citations that the UI parses and renders as interactive links is the current SOTA for citation UX in AI assistants.
  • Widget-trigger conditions - Each Rich UI element has explicit "must use if" and "do not use when" rules. This is a decision-tree approach to widget selection that prevents the model from decorating responses with unnecessary widgets. No competitor has this level of widget-gating precision.
  • Multi-source citation diversity - "You must base your answer on sources from diverse domains" and "more than half of citations from widely recognized authoritative outlets" are quality criteria for source selection, not just source retrieval. This is a meta-citation requirement that most AI assistants lack entirely.
📈📈 How It's Evolving
  • Citation system has grown from 0 to 80+ lines - GPT-4o had minimal citation instructions. GPT-5.6 has a full citation protocol with syntax, placement rules, diversity requirements, and word limits. This reflects the competitive pressure from Perplexity and the demand for source-backed answers.
  • Rich UI elements expanded from 2 to 7 - GPT-4o had weather and stock charts. GPT-5.6 adds sports schedules, standings, navigation lists, image carousels, and product carousels. Each new widget type corresponds to a new ChatGPT feature shipped between GPT-4o and GPT-5.6.
  • Product carousel exclusion list is new - The 15-category exclusion list for product recommendations did not exist in earlier prompts. It was likely added after legal review of the product carousel feature, which could expose OpenAI to liability for recommending regulated products.
  • Dedicated data tools - Weather, stocks, sports, and time now have dedicated tool endpoints that take precedence over web search when sources conflict. This is a shift from "search everything" to "use the authoritative API first," which improves response accuracy and reduces web search costs.

05Automations System: Built-in Scheduling & Condition Monitoring

✅✅ What It Does Well
  • iCal VEVENT scheduling - Using the standard iCal VEVENT/RRULE format for scheduling is a smart choice. It's a well-defined standard that handles recurrence (daily, weekly, monthly), exceptions (UNTIL, COUNT), and timezone-aware DTSTART. This avoids inventing a custom scheduling DSL that would require more prompt space and be more error-prone.
  • Three timing modes - exact_schedule (user-named time), flexible_schedule (dayparts with approximate times), and condition_watch (recurring checks until a condition is met) cover the full spectrum of scheduling needs. The mapping from user language to timing mode is explicit and deterministic.
  • Suggestion vs. creation boundary - "Prefer suggesting an automation" but "Do NOT create the automation unless the user asks for it." This is a consent boundary that prevents the model from creating automated tasks without explicit user approval. The suggestions are conversational and opt-in.
  • dtstart_offset_json - For relative one-time schedules ("in 4 hours"), the prompt uses JSON arguments to Python dateutil.relativedelta instead of calculating absolute timestamps. This eliminates timezone calculation errors, which are the most common bug in scheduling systems.
  • 7 concrete examples - The examples section covers Tahoe skiing, market reports, email monitoring, AI news watching, Flora briefings, laundry reminders, and gym reminders. Each shows the exact title, prompt, schedule, and timing_mode. This is few-shot learning at the prompt level.
⚠️⚠ What It Doesn't Do Well
  • Hourly frequency cap is limiting - "The highest frequency is once every hour." For stock price monitoring or breaking news alerts, hourly is too slow. The prompt acknowledges this ("interpret continuously as once per hour") but doesn't offer a workaround.
  • condition_watch has no exit condition - A condition_watch automation is recurring, but what happens when the condition becomes true? The prompt says "notify me if..." but doesn't specify whether the automation auto-disables after notification. This could lead to duplicate notifications or orphaned automations.
  • No conflict detection - If a user creates "remind me to do laundry at 3pm" and then creates another "remind me to call mom at 3pm," there's no instruction to check for scheduling conflicts. The model creates both independently.
🎯🎯 State of the Art
  • Agentic scheduling as first-class capability - No other consumer AI assistant has a built-in scheduling/automation system at this level. Siri has shortcuts, Google Assistant has routines, but ChatGPT's automations system is the only one that lets the AI create its own future tasks with natural-language prompts. This is a step toward autonomous agent behavior.
  • Self-addressed future prompts - The automation prompt is written as "an instruction that will be sent back to you on future runs." The model is essentially writing a prompt for its future self. This is a form of temporal self-delegation that is architecturally novel in consumer AI.
  • Daypart-to-time mapping - The explicit mapping (morning = 8am, afternoon = 3pm, evening = 7pm) is a practical heuristic that bridges human language to machine scheduling. This is more sophisticated than any competitor's time-parsing approach.
📈📈 How It's Evolving
  • Automations are entirely new in GPT-5.x - No prior OpenAI prompt had a scheduling system. This was introduced alongside the ChatGPT "tasks" feature in 2025-2026 and represents OpenAI's move from reactive chatbot to proactive agent.
  • From "I can't do things later" to "I can schedule things" - Earlier ChatGPT versions explicitly could not perform future actions. The automations namespace is a fundamental capability expansion that changes the product's identity from "chat" to "agent."
  • Suggestion pattern borrowed from Google Assistant - The "Want me to set that up?" opt-in pattern mirrors how Google Assistant suggests routines. OpenAI has adopted this UX pattern while making it more conversational and less scripted.

06Bio/Memory System, Developer Instructions & User Updates Protocol

✅✅ What It Does Well
  • Memory sensitivity taxonomy - The bio tool has a detailed taxonomy of what not to store: race, ethnicity, religion, criminal record, geolocation, political affiliation, health information. This is a privacy-by-design pattern that prevents the model from accumulating sensitive user data in long-term memory. The exception ("unless clearly requested") respects user autonomy while defaulting to privacy.
  • Always-call-on-trigger rule - "Anytime the user message includes phrases like 'remember that...' you should ALWAYS call the bio tool, even if the information has already been stored, appears extremely trivial or fleeting." This eliminates the judgment call that would cause the model to skip memory writes when it deems information unimportant, which would frustrate users who explicitly asked to remember something.
  • Asynchronous work prohibition - "You are incapable of performing work asynchronously... UNDER NO CIRCUMSTANCE should you tell the user to sit tight, wait." This is a critical trust boundary that prevents the model from making promises it cannot keep. It forces the model to deliver results in the current response, which is the only thing it can actually guarantee.
  • Update cadence protocol - The 15-second / 2-3 tool call cadence for user updates is a UX pattern that keeps the user informed during long reasoning chains. The 60-word cap prevents verbose updates that would themselves become noise. This is borrowed from human work culture (standup updates) and adapted for AI.
  • Partial completion over clarification - "Partial completion is MUCH better than clarifications or promising to do work later." This is an anti-laziness instruction that prevents the model from weaseling out of hard tasks by asking unnecessary clarifying questions. It forces best-effort responses.
⚠️⚠ What It Doesn't Do Well
  • "Creepy" is undefined - The instruction says "avoid overly-personal details that could feel creepy" but doesn't define what's creepy. This is a judgment call that varies by user and culture. The model must infer the boundary, which will produce inconsistent memory behaviors.
  • Sensitive data exception is broad - "Unless clearly requested by the user" allows the user to override the sensitive-data protections. But there's no verification mechanism - a prompt injection could trick the model into thinking the user requested to store health information. The exception is a security hole.
  • Hardcoded timezone - "The user's timezone is Atlantic/Reykjavik" is hardcoded for this specific leaked prompt (from user Asgeir's account). In production, this would be dynamic, but its presence as a hardcoded value means any timezone-dependent instruction that follows is user-specific, not generalizable.
  • Update cadence conflicts with image gen - "Do NOT give any plans or updates when using the image_gen tool" is an exception to the update cadence rule, but it's mentioned only in the cadence section, not in the image_gen section. A model reading the image_gen section alone wouldn't know to suppress updates.
🎯🎯 State of the Art
  • Persistent memory with sensitivity filters - The bio tool's sensitivity taxonomy is the most detailed memory-safety protocol in any consumer AI prompt. Claude's memory system (in Claude Mobile) has similar protections but doesn't enumerate categories as precisely. This is a privacy-engineering SOTA pattern.
  • Streaming update protocol - The 15-second update cadence with 60-word caps is unique to OpenAI. Neither Claude nor Gemini has a streaming-update protocol in their prompts. This reflects ChatGPT's real-time UI where users watch the model think, which is a product differentiator.
  • Anti-deferral instruction - "Never tell the user to wait" is a strong anti-laziness pattern that no other AI lab implements as explicitly. This forces the model to always produce output in the current turn, which is the right behavior for a synchronous chat product.
📈📈 How It's Evolving
  • Memory system evolved from "Custom Instructions" to "bio tool" - GPT-4o had custom instructions (static user-provided context). GPT-5.6 has the bio tool, which is a dynamic, model-managed memory system. This is a fundamental shift from user-curated context to AI-curated context, with privacy guardrails.
  • Sensitive data categories expanded - Earlier prompts had a shorter list of prohibited storage categories. GPT-5.6 adds trade union membership, explicit identification of personal attributes, and a nuanced distinction between "directly asserting" and "plausible mentions."
  • Update protocol is new - The streaming-update cadence did not exist in GPT-4o prompts. It was introduced when ChatGPT added the "watch me think" UI feature, which made the model's intermediate states visible to users. The update protocol manages this visibility.
  • Anti-deferral language escalated - GPT-4o said "don't promise future work." GPT-5.6 says "UNDER NO CIRCUMSTANCE" and "you are incapable of performing work asynchronously." The escalation reflects accumulated problems with models deferring work and then never delivering.

System Prompt Lab #2

The Big Takeaway GPT-5.6's prompt is the most complex consumer AI system prompt ever leaked - 2,661 lines managing 15+ tool namespaces across a 4-channel architecture. The key innovation is channel-based tool isolation: private reasoning and user-visible output are structurally separated, making the hidden chain-of-thought an architectural feature rather than a behavioral suggestion. The writing-blocks system, citation protocol, and automations framework transform ChatGPT from a chatbot into a multi-surface information agent. But the prompt's size (~28.5K tokens) is itself a design constraint - every additional instruction is a tax on every conversation.
