🔬 System Prompt Lab

▦ Key Takeaway Claude Opus 4.7's system prompt is a masterclass in economy of instruction. At 6K tokens, it achieves what GPT-5.6 needs 28K tokens for, through three key techniques: (1) XML structural scoping for behavioral isolation, (2) process-level rules instead of content lists (the meta-refusal trigger, the steel-manning doctrine), and (3) tool-conditional epistemology (behavior changes based on whether web search is available). The biggest evolution from 4.6 to 4.7 is the agentic transition: the addition of tool_search, capability_check, and acting_vs_clarifying sections. Claude is no longer just a chat assistant — it's being prompted as a tool-augmented agent that resolves ambiguity autonomously rather than asking the user. 🔵 XML-as-Architecture: The <claude_behavior> Pattern Anthropic wraps the entire system prompt in a single <claude_behavior> root tag, with 8 nested XML sections: product_information, refusal_handling, critical_child_safety_instructions, legal_and_financial_advice, tone_and_formatting (containing lists_and_bullets, acting_vs_clarifying, capability_check), user_wellbeing, anthropic_reminders, evenhandedness, responding_to_mistakes_and_criticism, and knowledge_cutoff. This is a semantic scoping pattern — the XML tags tell the model where one behavioral domain ends and another begins. This matters because transformer attention is distributed; without explicit boundaries, rules from different domains can bleed into each other. A formatting rule shouldn't influence a safety decision, and vice versa. The XML tags create attention barriers that keep domains isolated. Compare to GPT-5.6's prompt (Edition #2), which uses markdown headers for sectioning. Markdown headers are visual cues; XML tags are structural.
