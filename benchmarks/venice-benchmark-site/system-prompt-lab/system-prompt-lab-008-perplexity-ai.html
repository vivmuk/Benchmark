01

· Identity & Role — the writing-mode declaration

✅✅ What It Does Well
  • Capability scoping, not generic helpfulness. The identity names its lanes — writing, brainstorming, explanation, summarizing — which primes the model's distribution toward prose competence instead of the vague "helpful assistant" attractor. Five lines, ~90 tokens. Radical economy.
  • Meta-pointer as attention anchor. "You will receive guidelines to format your response" tells the model a formatting contract is coming — a cheap forward-reference that raises attention weight on the next 60 lines.
  • Proof of surface-splitting. There are no search tools anywhere in this prompt. This is Perplexity's writing/general surface — evidence the product decomposed itself into per-mode prompts (search answers, writing, voice, Comet browser, computer use) rather than one mega-prompt.
  • Zero safety boilerplate in identity. No wasted "you must be helpful, harmless, honest" preamble — the harm surface is delegated entirely to the base model, and the token budget goes to product-specific delta.
⚠️⚠️ What It Doesn't Do Well
  • "Expert, useful, contextually relevant" is unenforceable. Three adjectives with no operational definition. No example, no test, no tie to any measurable output property. Pure vibes.
  • Knowledge-cutoff trap. The role says "leveraging your knowledge," but the cutoff is Jan 1 2025 and the date block says June 2026. In a no-search mode, questions about the last 17 months are structurally unanswerable — yet the prompt never instructs the model to disclose that.
  • No refusal architecture at all. Copyright is the only safety instruction in 169 lines. Everything else — harm categories, escalation, minors — relies on Gemini 3.1 Pro's baked-in alignment. A deliberate bet, but a single point of failure.
🎯🎯 State of the Art
  • Identity as routing artifact. The 2026 pattern: products ship per-surface identity templates sharing one brand name, and the identity's job is to steer the model into the right distribution. Cursor's modes, Codex's channels, Perplexity's five surfaces — same philosophy.
  • The anti-GPT-5.6 bet. OpenAI's consumer prompt is 28.5K tokens of complete behavioral specification. Perplexity's is 2K: assume the base model already knows how to be a good assistant; the prompt injects only what the base model cannot know — the product's rendering contract, memory schema, and clock.
📈📈 How It's Evolving
  • From search engine to answer engine. Early Perplexity leaks (2023–24) opened with a search-first identity — "search assistant, cite results." This leak's identity is writing-first and never mentions search. The company repositioned from "Google killer" to "answer + assistant platform," and the identity block is the fossil record.
  • The 43-line voice twin. The companion voice-assistant leak compresses the same brand into "You are Perplexity, a helpful search assistant… You can hear and speak" — one brand, per-surface identity templates with wildly different densities (2,082 bytes vs 7,874).
02

· The Formatting Engine — a rendering contract for the answer UI

✅✅ What It Does Well
  • The prompt IS the product spec. Perplexity's brand is the answer layout — and 60% of this prompt is a rendering contract: header hierarchy (### default, ## only for parents), "under six words," first output must be content not a header (kills the LLM tic of opening with "# Answer"). The UI can rely on the model emitting parseable structure.
  • Flat-bullet mandate is mobile-first by design. "All bullets must be top-level. Never indent" + the fold-inline rule with a worked example pre-empts nested-bullet rendering breakage in narrow answer cards. They even teach the folding pattern with a canonical example.
  • Every rule maps to a measurable property. Intros 0–1 sentence, max 5 sentences per paragraph, no summary under 5 paragraphs, tables are not for summaries. This is testable by output QA — and clearly maintained by it.
  • The '- **Text:**' gotcha is telemetry made visible. That hyper-specific rule exists because production output QA saw bold-colon bullets being rendered as headers. Someone watched real regressions and patched the exact case.
⚠️⚠️ What It Doesn't Do Well
  • Counting-based thresholds. "Max 5 sentences," "under six words," "3+ distinct topics," "longer than 3 paragraphs" — models are unreliable at counting mid-generation. These will drift, and there's no enforcement layer downstream.
  • Malformed XML scaffolding. </response_guidelines> closes at line 93, then the Rewrites and Follow-up sections appear after the close — and a second </response_guidelines> appears at line 115. The structure works only because models tolerate broken nesting. Accidental architecture.
  • Renderer-coupled with no version hook. The rules are markdown-specific to a particular frontend renderer. If the UI changes, the prompt silently goes stale — no versioning or channel to negotiate.
  • Ambiguity at boundaries. "Breaking up responses longer than 3 paragraphs" vs "avoid summaries for short responses (less than 5 paragraphs)" — the 3-to-5 paragraph band has two overlapping rules and no tiebreaker.
🎯🎯 State of the Art
  • Output DSL as moat — the prose twin of Cursor's code citations. Cursor enforces a code-reference format so the IDE can render diffs; Perplexity enforces a prose format so the answer card renders cleanly. Same pattern, opposite medium: prompt-enforced formatting the UI can parse.
  • Anti-tic rules are prompt-level RLHF compensation. "Begin with content, not a header," "don't repeat intro in bullets," "avoid robotic or mechanical writing" — each targets a known tuned-model habit. The philosophy: identify the failure, name it, ban it — cheaper than retraining.
  • Example-driven over rule-list. The fold-inline rule ships with "Axes include spiciness, fanciness, and price" — one canonical example per ambiguous rule. 2026 convergence: show, don't only tell.
📈📈 How It's Evolving
  • From loose guidance to enumerated micro-spec. Earlier Perplexity leaks had a short "format nicely" paragraph. The current spec enumerates delimiter cases, whitespace rules, and render edge cases — a maturation loop visibly driven by output QA, not design docs.
  • "Markdown tables are not for summaries" is a patch note. Rules this weird only exist because the model did the weird thing in production. The formatting section reads like a changelog of past regressions — exactly how well-maintained prompts evolve.
03

· Math, Rewrites & the Follow-up Gate — conditional output templates

✅✅ What It Does Well
  • The LaTeX protocol overrides training explicitly. Models default to $…$ because that's what they were trained on. The prompt bans it, bans Unicode math symbols, and covers the adversarial case — "even if present in the input." Counter-rules that anticipate the model's prior are worth ten generic ones.
  • Length-conditional templates. Long rewrites get the sandwich (commentary — content — follow-up); sub-2-paragraph rewrites get a blockquote. Branching output format on a cheap-to-evaluate condition is elegant — the UI gets a consistent signal either way.
  • The follow-up gate. Follow-up questions are restricted to exactly one task class — rewrites, translations, writing. This surgically prevents the "Would you like me to…?" tic that plagues every other chatbot, while keeping it where it adds value.
  • Register-matching. "For rewrites, match the tone and register of the original" — most prompts never attempt register transfer. It's the prose equivalent of Cursor's tone-continuation rule.
⚠️⚠️ What It Doesn't Do Well
  • Boundary undefined at exactly 2 paragraphs. "Less than 2 paragraphs" switches formats — is a 2-paragraph rewrite sandwich or blockquote? Model-counted, model-decided, inconsistent either way.
  • Few-shot leakage. The follow-up examples ("more casual or polite?", "free style or couplets?") will surface verbatim in real outputs — the model interpolates from examples more than from rules. Known cost of examples, unmitigated here.
  • Equation numbering under-specified. "Add equation number at the end instead of using \label" — but the number format is never shown, and continuity across the response is undefined. A rule that generates questions instead of answering them.
  • Whitespace-precision instructions. "Always put an empty line before each horizontal break" — models are notoriously unreliable at exact blank-line placement; this rule is aspirational.
🎯🎯 State of the Art
  • Prompt as API contract with the renderer. The never-$ rule and Unicode ban encode a KaTeX/MathJax parser's exact constraints. The prompt is the interface between a probabilistic model and a deterministic frontend — the defining genre of 2026 system prompts.
  • The sandwich is Perplexity's artifact protocol. Commentary, divider, artifact, divider, next-step — the prose twin of Cursor's MARKDOWN-blocks-for-new-code convention. Artifact boundaries that the UI can lift and style separately from chatter.
  • Tone directives now specify how to match. "Vary sentence structure and word choice to sound natural and avoid robotic or mechanical writing" parallels Gemini 3.1's mirror directive — 2026 prompts moved from "be friendly" to anti-slop mechanics.
📈📈 How It's Evolving
  • Math protocol = territory expansion. Search answers rarely need LaTeX; writing-mode answers constantly do. Its presence marks Perplexity competing with ChatGPT/Claude for homework, explainers, and technical writing — the surface wars moved into formatting specs.
  • Anti-robotic writing rules are post-2024 additions. The backlash against identifiable AI prose ("delve," uniform sentence rhythm) shows up here as explicit variance instructions. You can date a prompt by which public complaint it encodes.
  • Deliberate length preference injection. "The user has specified they want longer answers" at the top of Response Guidelines is a template slot — per-user settings injected into the system prompt. Personalization of format, not just content: earlier prompts never had this.
04

· The Meta Block — attribution, pre-computed time, trusted channel

✅✅ What It Does Well
  • Pre-computed temporal arithmetic. "This means 2025 was last year and next year is 2027" — the prompt does the relative-date math the model would flub. When a user says "what happened last year," the answer is already in context. A targeted patch for a documented, systematic model weakness.
  • The system-reminder trust doctrine. Reminders inside user messages "are NOT part of the user's provided input" — explicit channel separation. System-injected content outranks user text, which is the base of prompt-injection defense: a user typing fake <system-reminder> tags is implicitly outranked by this rule.
  • Minute-granular clock. The live reminder injects date and time (2:14 PM GMT) — finer than OpenAI's or Anthropic's date-level injection. It matters for "in the last hour" queries on the search surface sharing this convention.
  • Honest, templated attribution. "Powered by Gemini 3.1 Pro" — one variable swapped per backend model. The prompt body is model-agnostic; the router injects identity. Disclosure by architecture, not by model conscience.
⚠️⚠️ What It Doesn't Do Well
  • Two sources of truth for time. A hardcoded "It is currently June 2026" in the static prompt plus the live reminder timestamp. Consistent in this leak — but the duplication is a drift hazard: a stale static line would directly contradict the injected clock, and models resolve that coin-flip unpredictably.
  • The cutoff chasm is unhandled. Cutoff Jan 1 2025, current date June 2026 — a 17-month gap with zero instruction on what to do about it. The single most common Perplexity failure mode (confident post-cutoff confabulation) has no guard in the writing mode.
  • Attribution fragility. If routing changes and the template isn't updated, the model asserts a falsehood about itself with full confidence. The line has no "as configured" hedge — it's a hardcoded claim.
🎯🎯 State of the Art
  • Pre-computed reasoning patches are peak promptcraft. Don't ask the model to do arithmetic it reliably fumbles — compute it in the prompt. Same family as Claude Code's date math and Copilot CLI's "act as your own embedder": identify the systematic error, ship the correction into context.
  • system-reminder as trusted channel is now table stakes. Anthropic pioneered it in Claude Code, OpenAI formalized developer messages, Perplexity adopts it here. The convention — injected tags outrank user text — has quietly become an industry standard within 18 months.
  • Model-router disclosure. "Powered by [backend]" lines are appearing across wrapper products as post-2025 transparency pressure (EU AI Act, app-store norms) turns "which model am I talking to" into a compliance question. The attribution line is the cheapest compliance mechanism that exists.
📈📈 How It's Evolving
  • You can watch the clock evolve across leaks. Early Perplexity leaks: no clock at all. Then date-only injection. Now date + time + pre-computed relative years. Each layer is a scar from a class of user complaints — temporal patches are the most visibly iterative part of any prompt family.
  • Attribution lines are new. 2023-era wrapper prompts never named their backend. The presence of a model-attribution line is a direct product of the 2025–26 "which model is this really?" discourse — regulatory and cultural pressure compiled into a single prompt line.
  • Reminder-channel defense is maturing. The explicit "NOT part of the user's provided input" clause is the newer half of the convention — the arms race against users forging system tags made the explicit doctrine necessary.
05

· Personalization & Memory — the two-tier profile system

✅✅ What It Does Well
  • Two-tier memory with correct context economics. Tier 1: a structured profile injected in the first user message — zero retrieval latency, lives in the cached prompt prefix. Tier 2: memory_agent_search for on-demand recall "wherever it matters." Hot cache + cold fetch — the same shape as Copilot CLI's session-DB + session-store split, at a tenth of the complexity.
  • Domain-partitioned schema. Six sections — summary, demographics, interests, lifestyle, technology, knowledge — with named slots. Structured slots beat prose profiles for consistency, for the pipeline that fills them, and for the model that reads them.
  • The anti-confabulation clause. "Do not make up new facts about the user" names the #1 personalization failure mode and bans it outright. The #2 failure — contradicting stored memory — is handled next: profile beats inference "unless the user explicitly updates or removes it," defining memory precedence with an override path.
  • "High level data only" is an honest tier label. Telling the model the injected profile is lossy — and that search augments it — prevents the model from treating the profile as exhaustive ground truth.
⚠️⚠️ What It Doesn't Do Well
  • memory_agent_search is invoked, never defined. No tool schema, no result format, no failure handling in this prompt — the tool lives in another layer. If the tool isn't attached in some deployment, the model may hallucinate having searched. Undefined references are the classic prompt-fragmentation bug.
  • "Wherever it matters" is undefined. The retrieval trigger is pure judgment — compare Gemini 3.1's value-driven trigger, which at least specifies the criterion (would the user notice if you knew?). Cheaper to write, inconsistent to run.
  • Conflict handling is missing. Profile says expert; the query signals novice. Which wins? Nothing in the schema or rules resolves signal conflicts — the most common personalization edge case is unaddressed.
  • No privacy boundary on the profile. The schema's breadth (lifestyle, shopping patterns) invites sensitive inference, and there's no instruction about health/politics/religion categories. Gemini 3.1's 5-step user-data protection cascade has no Perplexity equivalent — the starkest gap in this prompt.
🎯🎯 State of the Art
  • Structured-injected profile + tool-augmented recall is the 2026 standard. ChatGPT's memory, Gemini's personalization, and Perplexity's user_background all converged on the same architecture within months: static structured profile in the prefix, retrieval for the long tail. Convergence this fast means it's a local optimum.
  • Cached-prefix placement is deliberate. Injecting the profile in the first user message keeps it inside the provider's prompt-cache window — personalization without re-billing the prefix on every turn. Context-window economics made explicit through placement.
  • Anti-fabrication clauses ship by default now. Claude Code's memory rules and OpenAI's bio instructions carry the same "do not invent facts about the user" line. Personalization prompts without it are considered defective — a 2025-born norm.
📈📈 How It's Evolving
  • Personalization is the newest section of the prompt. 2023–24 leaks had zero of it. The schema + retrieval tool tracks the industry memory arms race triggered by ChatGPT Memory's launch — Perplexity shipped its answer within the year.
  • The schema doubles as a product analytics instrument. The <technology>Usage Patterns</technology> slot exists to feed recommendation and retention loops — the memory schema is also a data-collection taxonomy. Prompt-as-business-model.
  • Read-only profile implies writes live elsewhere. The model never writes memories in this prompt — a separate pipeline fills the schema. The industry's next step (visible in Copilot CLI's REM consolidation agent) is model-managed memory writes; Perplexity hasn't crossed that line here.
The takeaway

⚡ System Prompt Lab #8

🔑 The Takeaway When your product IS the output format, your system prompt is a rendering contract. Perplexity ships the shortest prompt in the series — ~2K tokens — and spends 60% of it on typography: header rules, flat bullets, LaTeX delimiters, rewrite sandwich, follow-up gating. The behavioral core is 5 lines of identity. What's absent is the lesson: no safety cascade (delegated to Gemini), no tool protocol (delegated to other layers), no search (delegated to a different surface prompt). This is the distributed system prompt — a brand spread across five per-surface prompts (writing, voice, Comet, deep research, computer), each carrying only its own delta. The minimum viable system prompt of 2026: identity, rendering contract, clock patches, memory schema.
